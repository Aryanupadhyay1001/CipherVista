# CipherVista - Database Design

**Version:** 1.0  
**Project Type:** AI-Powered Threat Intelligence Platform  
**Database:** SQLite

---

# 1. Introduction

This document describes the database design of CipherVista Version 1.

The database stores uploaded datasets, detected incidents, AI-generated reports, and prediction history. SQLite is used because it is lightweight, requires no external server, and is sufficient for Version 1.

---

# 2. Database Overview

Version 1 consists of three primary tables.

- Uploaded Files
- Incidents
- AI Reports

The relationship is shown below.

```

Uploaded Files
│
└──────< Incidents
|
└──────< AI Reports

```

---

# 3. Uploaded Files Table

Stores information about every uploaded dataset.

| Column | Type | Constraints |
|---------|------|-------------|
| id | INTEGER | Primary Key |
| filename | TEXT | NOT NULL |
| upload_time | DATETIME | NOT NULL |
| total_records | INTEGER | NOT NULL |

---

# 4. Incidents Table

Stores anomaly detection results.

| Column | Type | Constraints |
|---------|------|-------------|
| incident_id | INTEGER | Primary Key |
| file_id | INTEGER | Foreign Key |
| timestamp | DATETIME | NOT NULL |
| prediction | TEXT | NOT NULL |
| anomaly_score | REAL | NOT NULL |
| threat_score | INTEGER | NOT NULL |
| severity | TEXT | NOT NULL |
| status | TEXT | Default "Open" |

---

# 5. AI Reports Table

Stores reports generated by the Gemini AI engine.

| Column | Type | Constraints |
|---------|------|-------------|
| report_id | INTEGER | Primary Key |
| incident_id | INTEGER | Foreign Key |
| summary | TEXT | NOT NULL |
| possible_cause | TEXT | NOT NULL |
| recommendation | TEXT | NOT NULL |
| generated_at | DATETIME | NOT NULL |

---

# 6. Entity Relationships

```

Uploaded Files (1)
|
|------< Incidents (Many)
|
|------< AI Reports (Many)

```

Each uploaded dataset can produce multiple incidents.

Each incident has one AI-generated report.

---

# 7. Data Lifecycle

```

CSV Upload

↓

Uploaded Files Table

↓

ML Prediction

↓

Incidents Table

↓

Gemini Report

↓

AI Reports Table

↓

Dashboard

```

---

# 8. Database Constraints

- Every uploaded file receives a unique ID.
- Every incident belongs to one uploaded dataset.
- Every AI report belongs to one incident.
- Incidents cannot exist without an uploaded file.
- AI reports cannot exist without an incident.

---

# 9. Future Database Expansion

Future versions may include additional tables.

- Users
- Authentication
- Threat Intelligence
- CVE Database
- MITRE ATT&CK Mapping
- Audit Logs
- Live Monitoring Events

These tables can be added without changing the existing schema.

---

# 10. Summary

The CipherVista Version 1 database is intentionally simple and normalized. It separates uploaded datasets, detected incidents, and AI-generated reports into independent tables while maintaining relationships through foreign keys. This design provides a clean foundation for future expansion.
